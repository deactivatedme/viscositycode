## What this is

ViscosityCode is a rebranded fork of [Poracode](https://github.com/Porabuild/Poracode) (Apache-2.0): a React + TypeScript app that runs AI coding agents (Claude Code, Codex, Gemini CLI, Cursor, ACP agents, …) side by side. The fork keeps Poracode's backend, agent runtime, ACP/MCP, git/worktree and session-persistence code and replaces the look with a UI inspired by the Claude desktop app (warm greys, a sidebar with New / Search / Pinned / projects / profile, a bottom composer with pickers; inspiration only, no Anthropic assets). Earlier rounds used a Cursor-inspired layout. It adds features for someone paying for several AI subscriptions. The shipped desktop app is a Tauri shell (`desktop-tauri/`) around the bundled standalone host; the Electron app is kept only as the development harness (see [Desktop app (Tauri)](#desktop-app-tauri)).

- **Repository:** `https://github.com/deactivatedme/viscositycode`, branch `main` (remote `origin`).
- **Upstream:** remote `upstream` = Porabuild/Poracode. The fork starts at upstream commit `9b62823d5`; the local `master` branch tracks upstream. **Never push to `upstream`.**
- **History:** 56 fork commits on `main`, one feature per commit (`git log --oneline 9b62823d5..main`). The 2026-11-19/20 work (rows marked "uncommitted" below) is still in the working tree and has not been committed.
- **Licence:** Apache-2.0 kept; [NOTICE](NOTICE) and the README credit Poracode.

## Owner preferences (follow these)

- **Build end to end without stopping for approval.** Only stop for things that truly need the owner (credentials, irreversible or outward-facing actions).
- **English only.** Wrap user strings in Lingui macros and run `bun run i18n:extract` so the English catalog has them (otherwise production shows hashed IDs). Do **not** fill the 12 non-English catalogs; they fall back to English at compile time. This overrides the upstream rule about translating in the same change. Removing the other languages entirely was not requested.
- **Never steal focus.** Never raise or activate test windows (no `osascript … frontmost`). Drive the app over CDP only; anything needing a visible window must be scheduled with the owner.
- **Send real screenshots** of every implemented feature.
- **Logo:** the owner's "V" alone on a transparent background, no tile (`branding/assets/viscositycode-logo.png`; regenerate icons with `node branding/assets/build-icons.mjs --install`).
- **Look (decided 2026-11-20):** like the Claude desktop app, changed a bit: warm greys, a sidebar with New / Search / Pinned / projects / profile, a bottom composer with pickers. Inspiration only; never use Anthropic assets (logos, fonts, illustrations, copy).
- **No Effects, no Grok Bots, no welcome/home/discovery screens (decided 2026-11-20).** Do not bring back the animated background, agent effects, sound pack, per-project backgrounds or the Effects settings page. Grok Bots only redirected to the Grok Bot app and is gone; Grok as a model stays a Roundtable seat over the xAI API. Agents are detected automatically at startup with no screen, and the app opens on the last chat or a New session.
- **Usage surfaces show only AIs that are detected and set up** (Usage tab, sidebar rail, Subscriptions): no row for the unrelated upstream Vercel `fx` provider, no empty Gemini row.
- **Cursor cloud agents (decided 2026-11-20):** v1 scope is the Cloud inbox and Follow on the desktop only, cloud threads everywhere, and no notifications for agents that are not followed. A cloud agent launches from the project's `origin` repo on the current branch, which must be pushed (no local-only commits); otherwise refuse with a clear, localized message, never silently use the default branch. Followed agents are filed under Home. Remote/native inbox, REST steer and archive/delete are v2.
- **xAI API for Grok seats (follow strictly):** base `https://api.x.ai/v1` (US-only `https://us.api.x.ai/v1` serves text models grok-4.7/grok-4.6 only, +10% cost, no image/voice); `Authorization: Bearer $XAI_API_KEY`; text model `grok-4.7`, image model `grok-imagine-image-2.0`; use the Responses API `POST /v1/responses` with `input` (chat/completions is legacy); server-side tools `web_search`, `x_search`. The key stays in the main process (env `XAI_API_KEY` wins over the stored key).
- **Security:** never commit secrets or certificates (environment variables only); never auto-approve agent permissions; no phoning home to Poracode.

## Machine setup (the owner's Mac)

- Node 26.13.x comes from Homebrew (`/opt/homebrew/bin/node`), the pinned Bun is in `~/.local/bin`. Rust is installed (rustup in `~/.cargo/bin`; the crates pin 1.98.1, which has the `x86_64`/`aarch64` Apple and Windows MSVC targets installed), so `bun run dev` builds the native helpers. Java is **not** installed. The `upstream` remote's push URL is set to `DISABLED`. The GitHub CLI (`gh`) is installed and logged in. **Bare `gh` commands in a fresh clone act on Porabuild/Poracode, not the fork** (gh prefers the `upstream` remote): this checkout has `gh repo set-default deactivatedme/viscositycode` set; in a fresh clone run it once (or pass `-R deactivatedme/viscositycode`).
- Before tests, run:

  ```sh
  export TMPDIR="$(cd "$TMPDIR" && pwd -P)/"
  ```

  The `TMPDIR` realpath fix matters: macOS's `/var` → `/private/var` link otherwise breaks about a dozen path tests.

- 8 GB RAM: run focused tests (`bun run vitest run <paths> --maxWorkers=1`); the full suite takes about 20 minutes and must not run twice at once. Heavy commands queue on `scripts/heavy-run-gate.mjs`; that is normal.
- **Dev app:** `bun run dev` (stages the Rust helpers, including live_re, for this Mac; without Rust it only warns and falls back to JavaScript helpers, and live_re is absent). It uses its own data folder `~/.viscositycode-dev` (`PORACODE_BASE_DIR` overrides it), separate from the installed app's `~/.viscositycode`. It shows a real window on start, so check with the owner first if they are working (see Never steal focus).
- **Where settings live:** host settings (themes, account pools, saved playbooks) are `settings.json`, and shortcuts `keybindings.json`, in that data folder; the fork's view preferences (Lightweight mode in `viscosity:fx:v1`, which still holds the removed Effects groups unread; agent colours, Smart start, Mission Control, Subscriptions order/pretend/Customize, Playbooks view switches, sidebar view and Pinned collapsed) are localStorage keys `viscosity:*:v1`. The Windows backdrop choice is also mirrored to shell state `viscosity-window-material-v1`.

## How the fork is organised

- **Fork-owned code:** `src/renderer/viscosity/**`, `src/renderer/theme/viscosity/**`, `src/main/viscosity/**`, `src/shared/brand.ts`, `src/shared/viscosityRelease.ts`, `src/shared/viscosity/**`, `src/host/accountPools/**`, `src/shared/accountPools*.ts`, `src/host/viscosity/**`, `src/supervisor/viscosity/**`, `native/live-re/**`, `scripts/viscosity/**`, `branding/**`.
- **Upstream files the fork touches** start with `// Modified for ViscosityCode (fork of Poracode). See FORK_CHANGES.md.` (`#` in YAML), and each hook line carries `// ViscosityCode:`. Run `node scripts/viscosity/mark-modified-files.mjs` before committing: it adds missing notices and regenerates [FORK_CHANGES.md](FORK_CHANGES.md) (never edit that file by hand).
- **Branding:** `brandText()` rewrites "Poracode" → "ViscosityCode" in loaded catalogs, shared messages and displayed errors. Identity: app ID `com.viscositycode.app`, data folder `~/.viscositycode` (`-nightly`, `-dev`), CLI `viscositycode` / `viscositycode-next`. In-app updates are off unless `VISCOSITYCODE_UPDATE_REPO=owner/repo` is set at build time.
- **Names that stay "poracode" on purpose:** `PORACODE_*` environment variables, `poracode-*` CSS classes and storage keys, IPC channel names, protocol schemas, project `.poracode/` folders and hook file names are compatibility boundaries (ARCHITECTURE_NOTES §8, decision 2). Do not rename them to finish the rebrand. Likewise never change a command id or a `viscosity:*:v1` storage key once released.
- **Desktop-shell gate:** fork chrome is scoped to `html[data-vc-shell]` (desktop main window, not compact). Compact/PWA, the extension and the native iOS/Android apps keep upstream behaviour.
- **Design tokens:** `--vc-*` in `src/renderer/theme/viscosity/tokens.css`.
- **Extension points (use these instead of editing upstream):**
  - Palette commands: `registerViscosityCommands(key, factory)` in `src/renderer/viscosity/commands/viscosityCommands.ts` (ids `viscosity.*`; upstream's registry spreads `viscosityCommands()`).
  - Sidebar nav / status bar: `registerActivityBarItem`, `registerStatusBarItem` under `src/renderer/viscosity/layout/`. Activity items are now sidebar nav rows: top action items become rows, bottom action items go under More, and view items go in the header's view switch (Chats / Roundtable).
  - Center panels mount in `src/renderer/viscosity/layout/tabs/ViscosityCenterFrame.tsx`.
  - Mission Control tabs: `registerMissionControlTab` in `src/renderer/viscosity/missionControl/tabs.ts`.
  - Agent colours: spread `agentKindAttribute(kind)` on any per-agent element and style with `AGENT_ACCENT_CSS`.
  - Roundtable: `src/renderer/viscosity/roundtable/api.ts`; its playbook catalog is `roundtable/playbooks.ts`, and `buildAgentThreadConfig` (`engine/agentBrains.ts`) is the one place a seat's thread gets its playbook (seat over table; `null` means none).
  - Fork default shortcuts: `src/shared/viscosity/keybindings.ts` (`VISCOSITY_DEFAULT_KEYBINDINGS` and `VISCOSITY_BACKFILL_COMMAND_IDS`, spread into upstream's lists). Add an id to the backfill only if it never shipped a default.
  - Provider plan names for Subscriptions → Customize: the optional `subscriptionPlanNames` in a provider's renderer manifest.
  - Playbook themes: any preset or custom theme id in a playbook's `themeId`; CSS accents key off `html[data-vc-shell][data-theme-preset="<id>"]`.
  - Links to threads go through `activateThreadTab`, which ignores deleted or archived threads; hide such links with `useIsOpenableThread` / `useOpenableThreadIds` (`layout/tabs/openTabsStore.ts`).
  - **Register on import:** a feature's `index.ts` registers its sidebar nav/status bar items, Mission Control tabs and commands when it is imported, so a new feature does nothing until a file loaded at startup imports it (for example `ViscosityCenterFrame.tsx` or `src/renderer/commands/registry.ts`).
- **Provider isolation (upstream invariant):** no provider names or `kind === "<provider>"` branches in shared code; provider differences go through capabilities in the provider folder.

## Desktop app (Tauri)

Decided 2026-11-20: the Tauri app in [`desktop-tauri/`](desktop-tauri/README.md) is **the** ViscosityCode app (product name `ViscosityCode`, identifier `com.viscositycode.app`, data folder `~/.viscositycode`). It starts the bundled standalone host (`runtime/node lib/server.cjs serve` on `127.0.0.1:49380`) and shows the host's web client in one native window. Electron is no longer packaged or released. **Do not delete the Electron source** (`src/main`, the electron-builder config, the `dist*` scripts): it is the development harness (`bun run dev`, data folder `~/.viscositycode-dev`) and keeps upstream merges clean. Plan and research: `tmp/round2/design-tauri.json`; phase results: `tmp/round2/tauri-shell.json`.

**What the Tauri app lacks compared with the Electron app** (each is a regression for someone moving from the Electron 2.0.0 DMG; details in the [desktop-tauri README](desktop-tauri/README.md#release-gaps-owner-decisions-needed-before-a-public-release)):

- auto-update (no updater; replace the app by hand);
- the browser panel;
- computer use and the Chrome bridge;
- window blur and other window materials;
- the quick composer and its global shortcut;
- native file and folder pickers and drag-and-drop file paths (the web client's server-side folder browser and upload picker stand in);
- also: CI-built installers have no live_re debugger (`_server-artifact.yml` never runs `prepare-live-re`; a local `tauri:stage` includes it only when `resources/wsl-helpers/live-re` was already staged, as on this Mac), Windows installers carry no Linux MCP relay for WSL projects, no sleep inhibitor, no SSH environments, no provider login windows, no `viscositycode` command registration, and no Windows job object (a crashed shell on Windows can orphan the server).
- **Data folders created by the Electron app are refused**: Electron sealed the credential key with the macOS keychain, and the headless host will not adopt it ("Credential mode change requires explicit activation"). The app shows an error page and changes nothing. A migration is shared host work and is not built.

**Hybrid attach still works.** There is one owner per data folder. If the Electron dev app runs against the same folder (`PORACODE_BASE_DIR=~/.viscositycode bun run dev`) and owns it, the Tauri shell sees the root in use, pairs with that owner and becomes its client, and never stops it. Start the Tauri app first on a fresh folder: if Electron creates the folder, it seals the key and the Tauri app then refuses the folder (above).
